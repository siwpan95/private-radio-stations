## 🔍 进行中 / 已定位未完成

### 乐嗨 lehaitv.com（与秀色共用一个签名体系）

- 拉流端点仍是旧路径：`https://service.lehaitv.com/v2/room/{rid}/media/advanceInfoRoom`（JS 内 rootUrl 确认），但裸调返回 `statuscode:-998 权限检查错误，当前用户未登录`。
- 房间列表：`https://www.lehaitv.com/json/{allrooms,commonrooms,newCommonRooms}.json`（hotAnchorList[].roomid）。
- **签名体系（XSH5Utils，乐嗨/秀色共用）**：
  - 常量：`_hf_constants1="sowh1e"`, `_hf_constants2="1000ha"`, `_hf_constants3="butr12"`, `_hf_constants4="2000h5"`；
  - `EnmoliParamter` 类提供 getA123/getB2X/getC3Y/getDX34；`ayz(a,b)` 返回两个字符串之一（DES 密钥候选 = `"showself_h5_XSH5Utils"` 或 `"showselfAnchorVisitorParameters"`）；
  - `XSH5Utils.encryptByDES/decryptByDES`：CryptoJS DES-ECB-Pkcs7，密钥 = ayz 结果；
  - 参数签名：`brm(e)` = cls(排序 key=value&) 经 `pt()` 十步变换链（aa/ab/…/ax/az，每步与密钥混合）；
  - `getSyncJSONData` 请求包装在**另一文件**（未定位），签名参数名未知。
- 下一步：定位 getSyncJSONData 所在 bundle → 确认签名参数名与变换链 → 用 pycryptodome 复刻（F:\Python314 已装）。若签名仅用于防刷，可尝试抓浏览器实际请求对照。

### 六间房 v.6.cn

- 站点存活（首页 797KB，房间链接 `v.6.cn/{rid}`，海报持续更新到 2026）。
- 房间页（如 10999）无内嵌流数据；API 埋在 `vr0.6rooms.com/hao/dll3/dll{1,2}_*.js` 大包内（主包 bl.v1.8.35.js 仅 49KB 无端点）。
- 旧链 `rio.6rooms.com/live/?s={uid}` 已 404。下一步：grep dll1/dll2 找拉流 API（预期 `vapi.*.6rooms.com` 或 `live.*` 域名）。
- **更新（深夜续探）**：房间页内联 JS（10KB）含完整房间数据：`roomid`、`uid`、`flvTitle.flvtitle`（如 `v87803401-222366390`）、`rtmp_ip: wliveup.6rooms.com`（推流口，非拉流）；m.6.cn 移动房间页无内嵌流数据；`entry.a18ad633fa99f000.js` 是 webpack 壳，播放器 chunk（4016/5802）为 UI 包、无拉流域；flv/hls/live/vapi/api.6rooms.com 等候选拉流域全部 DNS 死。
- 结论：拉流地址由播放器 SDK 内的私有 API/硬编码域名产生（可能含鉴权）。下一步：用浏览器开发者工具对 m.6.cn 直播页抓 XHR，直接看拉流请求——比静态分析更快。
